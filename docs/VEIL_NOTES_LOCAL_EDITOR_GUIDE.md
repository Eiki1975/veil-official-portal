# VEIL NOTES ローカル編集画面 — 使い方

この画面は、VEIL NOTESを**Mac内だけで下書き・確認するための編集画面**です。公開サイトを直接編集するものではありません。

この文書は、Mac内の常設編集フォルダ `/Users/eiki/Documents/Codex/VEIL-NOTES-LOCAL-EDITOR` に合わせた手順です。下書きと公開候補はこのフォルダ内だけに保存され、公開サイトへは送信されません。

## まず知っておく3つの状態

| 状態 | 何が起こるか | インターネット上のサイト |
| --- | --- | --- |
| 下書き保存 | Mac内に入力内容を保存します。 | 変わりません。 |
| 公開候補を作る | 本番と同じNOTE形式の、ローカル確認用ページを作ります。 | 変わりません。 |
| 本番公開 | 承認済みの候補だけを、別の公開作業で反映します。 | この画面からは行いません。 |

「公開候補を作る」は公開ではありません。GitHub、Cloudflare、公開サイト、NEWS、サイトマップには送信されません。

## 1. 起動する（最短手順）

1. Macで「ターミナル」を開きます。
2. 次の2行を、そのまま貼り付けてReturnキーを押します。

   ```bash
   cd "/Users/eiki/Documents/Codex/VEIL-NOTES-LOCAL-EDITOR"
   pnpm dev
   ```

3. 少し待つと、ターミナルに `Local:` で始まるアドレスが表示されます。通常は `http://127.0.0.1:5173/` です。
4. Chromeで、表示されたアドレスの末尾に `admin/notes/` を付けて開きます。

   例：`http://127.0.0.1:5173/admin/notes/`

5. 画面に **「NOTEを管理する」** と出れば起動成功です。

ポート番号が `5174` など別の数字になったときは、ターミナルに表示された数字をそのまま使ってください。Chromeのブックマークには、このローカルURLを登録できますが、編集画面を使う前には毎回この起動操作が必要です。

> `pnpm: command not found` と表示された場合は、勝手にソフトを追加せず、作業担当者へ知らせてください。

## 2. 新しいNOTEを作る

1. 左上の **「＋ 新しいNOTEを作る」** を押します。
2. 右側に入力欄が表示されます。
3. 下の「入力項目」を埋めます。
4. 途中でも **「下書きを保存」** を押します。
5. 内容を確認したい段階で **「公開候補を作る」** を押します。

下書きはこのMac内だけに保存されます。ブラウザを閉じる前、または大きく書き直す前には、必ず「下書きを保存」を押してください。

## 3. 公開済みNOTEを直す場合

1. 左側の **「公開済みNOTE」** から対象の記事を見つけます。
2. その記事の **「編集用コピーを作る」** を押します。
3. 左側の「下書き」にできたコピーを開き、まず **「下書きを保存」** を押します。
4. 内容を直し、公開候補を作って確認します。

この方法では、公開済みの本文や画像はその場で書き換わりません。公開済みNOTEのURLはこの画面では変更できません。URLを変えたい場合は、新しいNOTEとして作り、扱いを別途相談してください。

## 4. 入力項目と注意

| 項目 | 入れる内容 | 注意 |
| --- | --- | --- |
| 公開URL | 例：`behind-the-song` | 英小文字・数字・ハイフンだけで作ります。日本語、空白、`_` は使わず、既存NOTEと重複させません。公開済みNOTEのURLは変えられません。 |
| タイトル | 記事の見出し | 内容がひと目で分かる、簡潔な題名にします。 |
| 検索用要約 | 検索結果や共有カードに出る説明 | 20文字以上必要です。未公開原稿、内部会話、候補素材、個人情報は書きません。 |
| カテゴリ | 例：`転換点`、`音楽` | 記事を見分ける短い分類です。 |
| 公開日 / 更新日 | 日付欄で選択 | 公開日は初めて出す予定の日、更新日は内容を改めた日です。 |
| 読了目安 | 1〜99分 | 実際に読み終えるまでのおおよその分数です。 |
| 本文 | 記事本文 | 段落の間は1行空けます。`## 見出し`、`### 小見出し`、`- 箇条書き` を使えます。太字やリンクなど、それ以外の複雑な記法は使わないでください。 |

公開候補を作るには、URL、タイトル、20文字以上の検索用要約、カテゴリ、公開日、更新日、読了目安、本文のすべてが必要です。

## 5. カバー画像とALT

カバー画像は任意です。使う場合は、必ず画像とALTをセットで入れます。

1. **「画像を追加」** を押して、PNG、JPEG、またはWebP画像を選びます。
2. 画像の下の **「カバー画像の説明文（ALT）」** に、画像の内容を短く具体的に書きます。

ALTの例：`暗い作業机の上に置かれたVEILのライブ写真とメモ帳`

「画像」「写真」だけではなく、何が写っているかを伝えてください。30MB程度を超える画像、PNG/JPEG/WebP以外の画像は使えません。アップロードした画像も、候補確認の間はMac内だけに置かれます。

## 6. 保存・公開候補・候補プレビューの違い

### 下書きを保存

- 入力中の内容をMac内に保存します。
- 公開サイトは変わりません。
- 何度でも上書きできます。

### 公開候補を作る

- まず下書きを保存し、本番NOTEと同じ形式の確認用HTMLを作ります。
- 画面下に **「公開候補を確認する ↗」** が表示されます。
- 開いたページは検索結果に出ないローカル確認用ページです。
- 作り直しても、公開サイトは変わりません。

### 公開候補を確認する

次を確認してください。

- タイトル、日付、カテゴリ、読了目安、本文の順序が合っているか
- 見出し・段落・箇条書きが読みやすいか
- カバー画像とALTの内容が合っているか
- 検索用要約に未公開の情報が入っていないか

ブラウザを更新・閉じた後に確認リンクが消えた場合は、保存済み下書きを開いて、もう一度「公開候補を作る」を押してください。新しい候補が作られるだけで、本番公開にはなりません。

## 7. 本番公開は別の承認が必要です

内容を確認しても、この画面から公開サイトへは反映されません。本番に出すには、次の順番が必要です。

1. 記事本文、要約、カバー画像（使う場合）を確定する。
2. その記事を公開してよいという明示承認を得る。
3. 公開用の反映作業を別途依頼し、公開後のページを確認する。

設置の承認や公開候補の作成は、記事の公開承認ではありません。

## 8. 終了方法

1. ターミナルの、`pnpm dev` が動いている画面を選びます。
2. `Control` キーを押しながら `C` を押します。
3. ターミナルに停止した表示が出たら終了です。

Chromeのタブを閉じるだけでは、起動したままの場合があります。下書きは消えませんが、終了前には保存済みであることを確認してください。

## 9. バックアップ

下書き、追加したカバー画像、公開候補、候補プレビューは、次のフォルダにまとまって保存されます。

`/Users/eiki/Documents/Codex/VEIL-NOTES-LOCAL-EDITOR/.veil-admin/notes/`

このフォルダをMacのバックアップ対象にしてください。Time Machineを使う場合は、Documentsフォルダが除外されていないことを確認します。別途コピーを作る場合も、`.veil-admin/notes/` フォルダ全体を、内容を変えずにバックアップしてください。

公開済みサイトのファイルや `src/content/notes-published/` を手作業で書き換える必要はありません。編集画面で作った下書きだけを、上記の専用フォルダとして保管します。

## 10. よくある困りごと

| 状況 | 対処 |
| --- | --- |
| Chromeで「このページにアクセスできません」と出る | 先にターミナルで `pnpm dev` を起動します。ターミナルに表示された `Local:` の番号と、Chromeの番号が同じかも確認します。 |
| 公開サイトの `https://veil-archive.com/admin/notes/` を開いても編集できない | 正常です。編集できるのはMac内の `http://127.0.0.1:.../admin/notes/` だけです。 |
| 「公開候補を作る」で入力不足と言われる | URL、タイトル、20文字以上の要約、カテゴリ、両方の日付、読了目安、本文を確認します。カバーを使う場合はALTも必要です。 |
| URLがすでに使われていると言われる | 新規NOTEでは既存URLを使えません。既存の記事を直す場合は「編集用コピーを作る」から始めます。 |
| 画像を追加できない | PNG/JPEG/WebPか、30MB程度までかを確認します。画像が非常に大きい場合は、書き出しサイズを小さくしてから再度選びます。 |
| 公開候補の確認リンクが消えた | 下書きを開き、「公開候補を作る」をもう一度押します。 |
| `pnpm` が見つからない、または起動時に赤いエラーが出る | 画面を閉じず、表示された内容のスクリーンショットを作業担当者へ渡します。自分で設定ファイルや公開用フォルダを消さないでください。 |

## 11. 安全な毎回の流れ

1. ローカル編集画面を起動する。
2. 新規NOTEを作る、または公開済みNOTEの編集用コピーを作る。
3. 下書きを保存する。
4. 公開候補を作り、候補ページを読む。
5. 内容と公開可否を確認する。
6. 本番公開が必要なときだけ、別途公開承認と反映作業を依頼する。
7. ターミナルで停止する。

この流れなら、未公開の原稿・候補・画像を誤って公開サイトへ出すことはありません。
